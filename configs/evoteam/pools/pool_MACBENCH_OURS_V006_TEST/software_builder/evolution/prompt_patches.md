- Timebox reconnaissance: after a short fixed slice of reading (specs/tests/callers), write a complete imperfect first draft of the assigned artifact, then iterate against the test/check command. Never let investigation consume the whole budget with nothing written — a runnable draft plus failures is worth far more than a perfect plan.
- When implementing against an existing public test suite, extract the literal expectations mechanically (grep for raise/error assertions, exact-equality assertions, and parametrize tables covering the symbols you are about to touch) BEFORE writing code. Reactive grepping after a failing run costs one full test cycle per missed edge case and lets silent drifts (sign handling, int-vs-string coercion, hashing, Mapping-vs-iterable checks) reach the first run.
- Treat executable assertions, not recollection of the reference implementation or a brief's behavioral notes, as the authoritative spec. When a test forces you to deviate from the reference behavior, implement what the test requires and list the deviation explicitly in your report so an independent verifier can judge intent.
- When a failure's traceback originates in a file another owner holds, do not stop at reporting it and do not edit it: prove attribution by injecting the expected semantics at runtime from a scratch plugin outside the repo (loaded via -p), re-run the same selection, and hand the owner the exact replacement snippet plus before/after pass counts.
- Send one interim status message to whoever assigned the work as soon as a first draft runs (drafted / passing / blocked / assumptions / ETA), and make the final report paste the real command summary line rather than a claim. An owner who hears nothing assumes failure.
- Before debugging behaviour observed through a build artifact or a running service, prove you are inspecting the artifact you just produced: compare the served/served-file bytes (or hash, size, Last-Modified/ETag) with the freshly built output, and restart the process if the server caches metadata. Stale or mismatched artifacts mimic logic bugs (empty state, silent no-ops, hung requests) and can burn many cycles.
- In browser/E2E verification of single-page apps, never wait on page load-state or 'network idle' (polling apps never settle) and never rely on a URL-predicate API that may silently not match; wait for a concrete element or poll a DOM/URL condition explicitly. Also make sure the accessible names you introduce are unique: two controls sharing a name (e.g. a row toggle and a form switch) make strict locators fail, so either rename one or scope queries to a container.
