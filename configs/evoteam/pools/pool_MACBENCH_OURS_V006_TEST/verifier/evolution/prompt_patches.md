- Read-only verification hygiene: write nothing into the shared workspace (disable caches, bytecode and temp outputs inside it; keep scratch outside), and run key suites/commands more than once, recording each result — a single run is only a snapshot of a tree others may be editing concurrently.
- Behavioral results from a running service only count if the process postdates the last source change: compare process/pid start time with file modification times, re-run affected checks after a restart, and treat differing served-artifact hashes/sizes as evidence the target is still moving.
- Ground every expected value in production source or the public tests (literal strings, exact error texts, payload shapes) before reporting it; then audit the environment's capability envelope (do the subject accounts hold the model-level permissions/roles the check needs? do referenced catalog objects exist? what did the fixture pre-seed?) and classify each failure as real defect vs. fixture/harness limitation, stating which in the report.
- For nested/parent-child write APIs, verify a get-then-put round trip of the exact retrieved representation in addition to partial updates — nested-field validation asymmetries usually surface only on full-object writes; also compare nested ids before and after a write to detect delete-and-recreate semantics that break id-caching clients.
- Name every probe record with a unique prefix, delete by that prefix inside the same script that created it, and re-read the affected collection counts (including cascaded child collections) to prove the environment returned to baseline; report anything you cannot restore.
- Never treat the exit code of a downstream pipeline stage (pager, tail, grep) as the exit code of the command under test: redirect the command's output to a log, capture its status directly, then inspect the log.
- Send newly discovered blocking or contradicting evidence (a broken postcondition, a refuted attribution, a new failure cluster) to the owning agent immediately as a short partial report instead of holding it for the final analysis.
- When mining a specification for hidden requirements, make 'behaviour through composed/wrapped objects' an explicit checklist dimension: a capability that works when used directly usually must also work when the same object is wrapped in a container or forwarded through an intermediate, and that propagation is the most commonly missed requirement.
- Record an immutable fingerprint (id plus version/etag/modified timestamp) for every artifact you read while preparing to verify, and re-read that fingerprint before signing off — re-reading the fingerprint proves the artifact did not move between your passes, whereas re-reading the content only proves it is currently correct.
- Before reporting a numeric discrepancy, re-derive the count and the basis from live primitive records (how many documents exist, which ones the definition includes, whether a reversal document is separate from the original) — a suspected off-by-one is far more often a wrong assumption about which records count than a real defect, and a retracted false alarm costs the team more than the extra derivation step.
