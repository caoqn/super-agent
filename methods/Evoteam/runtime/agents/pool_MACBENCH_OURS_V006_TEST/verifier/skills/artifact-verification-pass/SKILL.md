---
name: artifact-verification-pass
description: Independent, read-only verification procedure for build/package systems that emit installable archives (wheels, sdists, tarballs, zips), including checksum, reproducibility, round-trip and fresh-consumer checks
trigger: When asked to verify that a build/packaging backend or archive-producing tool produces correct, installable, reproducible artifacts
---

Use this checklist when the deliverable is an artifact (archive, package, binary bundle) produced by code you did not write. Run every step read-only and keep scratch output outside the project tree.

1. **Official check first.** Run the repository's documented check entrypoint exactly as documented (not your own ad-hoc invocation), capture the tail of the output, and record pass/fail/skip counts plus the interpreter version. Expect skips; confirm each skip reason is environmental (e.g. interpreter version) and not a silently disabled assertion.
2. **Enumerate the archive.** Build the artifact into a scratch directory, then list all members in order. Verify every member belongs under the expected top-level prefix, that no build leftovers (temp files, caches, bytecode, duplicate peers) are present, and that the expected metadata/checksum/index files exist.
3. **Recompute checksums.** For each entry listed in the archive's checksum/index file: parse the record, recompute the digest over the member bytes with the stated algorithm, confirm encoding rules (e.g. urlsafe base64 without padding) and byte size match, confirm the index file's own entry has empty digest/size, and confirm every member appears exactly once with no unlisted extras.
4. **Header/metadata semantics.** Parse the metadata file(s) with the standard library parser used by consumers and assert required fields and their values, plus that the parse reports no defects (bad folding, duplicate keys, missing blank line before the body).
5. **Reproducibility.** Build the same artifact twice into two different directories under a fixed timestamp environment variable and compare with a byte-level tool (cmp + sha256). Then assert the timestamp mapping explicitly: the epoch value projects to a concrete UTC date-time, and out-of-range values clamp to the format's documented minimum. Check permission bits from the archive's raw mode field (e.g. shift the external attribute) instead of trusting the extracted file system.
6. **Round-trip.** Extract the source artifact into a clean scratch directory, build again from inside the extracted tree, and verify the second artifact is valid and contains the same code + metadata members. This catches archives that omit inputs required to rebuild.
7. **Fresh-consumer install.** Install into an isolated environment that does not contain the builder or a source checkout (virtualenv + `--no-index`, or unzip onto a temp path). Then import the installed module, import the entry-point target, exercise resource loading, and run any generated console command. If network/index access is unavailable, state that explicitly and use the unzip-plus-path fallback — never claim a pip result you did not obtain.
8. **Import/API smoke.** Import every public module of the package in a subprocess so import-time errors (missing vendored imports, circular imports) surface independently of the test suite.
9. **Report shape.** One row per requirement: PASS/FAIL/UNVERIFIED, the exact command, and 1-3 lines of key output. List defects with a minimal reproduction command and the exact traceback; never patch the code yourself.
